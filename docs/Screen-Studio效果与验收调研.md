## 可确认的功能事实

### 鼠标与光标

- 官方说明称其将原始录制中的光标隐藏、再依据鼠标位置数据后期叠加，因此可以在录制后调整光标尺寸、平滑其移动，并以高分辨率版本替换已知系统光标。[官方“自定义 macOS 光标尺寸”说明](https://preview.screen.studio/guides/custom-macos-cursor-size)
- 官方“Cursor”指南列出光标尺寸、隐藏静止光标、循环回到首位置、移动时旋转、停止末尾移动、去除抖动，以及“优化原始光标类型”等选项；后者的公开含义是减少录制中光标形状的快速切换。[官方 Cursor 指南](https://screen.studio/guide/cursor)
- 官方“Animations”指南把光标动画速度分为 Smooth、Medium、Rapid、None；它没有公开各档的曲线、滞后或采样规则。[官方 Animations 指南](https://screen.studio/guide/animations)
- 两个本地样本的鼠标事件确实出现 `arrow`、`pointingHand`、`iBeam` 三种 `cursorId`，光标描述数据另有热点和标准尺寸。详见 [Screen-Studio轨迹格式调研.md](Screen-Studio轨迹格式调研.md)。这证明输入需保留形状和热点，不能只处理坐标。
- 两个样本项目都保存了 `cursorSize: 1.5`、`hideCursor: false`、`disableMouseMovementSpring: false`、`optimizeOriginalCursorTypes: true`，并保存了 `mouseMovementSpring: { stiffness: 470, damping: 70, mass: 3 }`。这些只是样本配置；字段名和数值不能证明具体使用的物理模型或应用默认值。
- 官方也支持按片段关闭平滑鼠标，举例是下拉菜单，以保留准确的原始移动。[官方“Disable smooth mouse movement”指南](https://screen.studio/guide/disable-smooth-mouse-movement)

### 点击反馈

- 官方路线图把点击视觉效果描述为“ripple 或 expanding circle”，更新日志还提到 ripple、shockwave 与 circle click effect；这能确认点击反馈属于产品功能，但公开材料没有给出颜色、半径、持续时间、触发在按下还是抬起事件的定义。[官方 Roadmap](https://screen.studio/roadmap)、[官方 Changelog](https://screen.studio/changelog)
- 两个样本的 `config.clickEffect` 都为 `null`，所以样本本身没有启用可供观察的点击样式；`mouseClickSpring` 字段也不能证明它驱动哪一种点击图案。

### 缩放、进入、停留、退出和跟随

- 官方说明：录制时默认依据点击自动创建缩放；缩放可删除、禁用、添加，边缘可拖动以调整持续时间。[官方“Adding & Editing zooms”指南](https://screen.studio/guide/adding-editing-zooms)
- Auto zoom 聚焦范围内的点击位置；若该范围没有点击，官方明确说它不会缩放到任何区域，应改用 Manual zoom。Manual zoom 使用用户选定的目标点和可调倍率。[官方 Auto zoom 指南](https://screen.studio/guide/auto-zoom)、[官方 Manual zoom 指南](https://screen.studio/guide/manual-zoom)
- 官方存在“Instant Animation”开关，表示可选无动画的瞬时缩放；其余普通缩放具有动画，但公开资料未定义进入、退出或停留的确切时长。[官方 Instant zoom 指南](https://screen.studio/guide/instant-zoom)
- 两个样本各有一个已保存且未禁用的 `zoomRanges`：

| 样本 | 源录制范围（ms） | range 类型 | 区间（ms） | 倍率 | 其他已保存字段 |
| --- | ---: | --- | ---: | ---: | --- |
| `Area 2026-09-11 00:19:01` | 0–19799.710 | `follow-click-groups` | 4142–10609 | 2 | `snapToEdgesRatio: 0.25`、`glideSpeed: 0.5`、`hasInstantAnimation: false` |
| `Area 2026-09-11 01:08:34` | 0–9520.459 | `follow-click-groups` | 1473–8720 | 2 | 同上 |

  两个样本当前只有一个切片且 `sourceStartMs: 0`、`sourceEndMs` 等于录制范围、`timeScale: 1`，故这里的项目时间与源视频时间相同。这个等价关系不能延伸到将来有剪辑、暂停拼接或倍速的项目；届时应单独定义源时间与项目播放时间的映射。

`follow-click-groups`、`snapToEdgesRatio`、`glideSpeed` 是本地 JSON 中的字段名。结合官方“Auto zoom 追随点击位置”的说明，可以合理称其为**点击驱动的缩放范围**；不能据此断言其点击分组、边缘贴合或跟随路径的具体算法。

## 第一阶段建议的范围

### 时间轴输入：只执行显式区间

**我们的建议：第一阶段的 `session.json` 仅执行用户明确写出的缩放区间，不从点击自动生成区间。** 这与根目录开发说明所列“缩放起止时间/目标点/倍率”直接对应，结果可复现、可测试，也能覆盖无点击的手工聚焦。

点击自动生成区间应作为后续独立能力。它至少还需产品规则来决定：哪些点击忽略或合并、相邻点击怎样分组、区间从点击前后各延伸多久、多个区间重叠时怎样处理、没有点击时怎样处理，以及是否将目标改为手工位置。官方公开说明确认有自动创建和可编辑区间，但未公开这些规则，不能把样本里的一个 `follow-click-groups` 当成规范。

建议的首期最小输入语义如下，字段名可在数据格式设计时定稿：

```json
{
  "startMs": 1500,
  "endMs": 5000,
  "target": { "x": 0.72, "y": 0.38 },
  "scale": 2.0
}
```

- `startMs`、`endMs` 均以源视频起点为零的毫秒表示；要求 `0 <= startMs < endMs <= 视频时长`。
- `target.x/y` 是录制画面归一化坐标，不是输出视频像素；渲染时将放大的可视区域夹在源画面边界内。
- 区间表示效果的完整生命周期（进入、停留、退出都落在 `[startMs, endMs]` 内）。这是**我们的首期约定**，不是从 Screen Studio 反推的文件语义。
- 首期禁止重叠的启用区间；校验器报错并指明区间索引。这样避免多目标、倍率和进入/退出曲线的优先级问题。

`instant`、`followCursor` 和按片段关闭平滑均为可选扩展，不列入首期最小输入格式或验收。它们需要新增明确的时间线语义，且不能仅因名称相近就复刻 `follow-click-groups`。

### 我们建议的默认值

这些值为本项目的可调起点，不是 Screen Studio 默认值，也未经过本机逐帧预览比对。

| 项目 | 建议默认值 | 原因与验收口径 |
| --- | --- | --- |
| 光标尺寸 | 原光标标准尺寸的 `1.5×` | 两样本恰好保存为 1.5；作为易读且不过分抢眼的起点。热点必须仍落在事件坐标。 |
| 光标位置 | 保形、无过冲的时间插值 | 每个输出帧由事件时间取样；不按数组下标取样。平滑应保持选定锚点与点击锚点，允许滤除其他高频噪声采样。 |
| 光标形状 | 在 `cursorId` 事件时切换，使用对应热点 | 首期不做形状之间的视觉过渡或“优化”规则，避免臆测。 |
| 点击反馈 | 按 `mouseDown` 显示单个圆环涟漪：`380 ms`、从 `12 px` 扩至 `56 px`、透明度从 `0.75` 衰减至 `0` | 这是通用的圆环反馈，不声称等同于 Screen Studio 的 ripple/shockwave。若事件只有 `mouseUp`，校验应报错或按明确兼容策略处理。 |
| 缩放倍率 | `2.0×` | 两个样本区间都是 2；仅作本项目建议，允许事件覆盖。 |
| 进入/退出 | 各 `250 ms`，余下时间停留；若区间短于 `500 ms`，两段按等比例压缩 | 定义完整且可测的生命周期；用单调 ease-in-out，要求首尾无突跳。 |
| 跟随 | 可选后续扩展 | 如后续启用，采用平滑后鼠标位置作为相机目标，并进行边界夹取。 |
| 瞬时缩放 | 可选后续扩展 | `instant: true` 时在 `startMs` 直接切到目标倍率、在 `endMs` 直接回到 1；作为单独、可测试的分支。 |

## 第一阶段可验收要求

以下是对本项目渲染器的验收，和 Screen Studio 的商业产品外观无关。

1. **时间与坐标。** 对单段、无倍速的 MP4，事件时间由 `(processTimeMs - processTimeStartMs) / 1000` 对齐；按录制 `bounds` 归一化后映射到实际解码帧尺寸。首帧、末帧、视频外事件、非递增时间和越界坐标均有明确校验结果。
2. **鼠标平滑。** 给定相同 MP4、JSON 与帧率，多次渲染每帧光标位置相同。关闭平滑时，帧位置来自相邻原始事件的时间线性插值；开启时可改变中间路径但不得产生 NaN、越界或明显过冲。平滑必须保留显式选定的锚点和点击锚点，允许偏离其余高频原始采样以去除抖动。应有含稀疏采样和快速转向的合成测试。
3. **形状与热点。** 在 `cursorId` 切换后的首个相应时间帧，采用新形状；绘制位置以热点对齐。缺少未支持的形状资源时必须有明确的通用光标回退或校验失败，不能静默画错位置。
4. **点击。** 每个有效 `mouseDown` 只产生一次、可预测时长的反馈；无点击项目不产生反馈；多个快速点击各自独立；在 `mouseDown` 对应帧，光标热点和点击反馈中心都命中经当前缩放变换后的点击位置。输出帧可由指定时间 PNG 验证。
5. **缩放时间轴。** 对一个足够长区间：区间开始前为 `1×`，进入段连续到目标倍率，停留段保持目标倍率，退出段连续回 `1×`，区间结束后仍为 `1×`。目标在进入和退出期间连续移动，在停留期稳定；目标靠近边缘时，相机目标的夹取规则须明确，且画面无黑边、无源画面外采样。
6. **组合顺序。** 先确定当前缩放的源画面视口，再把光标和点击中心映射到输出空间；因此点击与光标在放大画面中对准其指向的内容。PNG 检查应覆盖进入、停留、退出各至少一帧。
7. **范围限制。** 首期只承诺单段、无光标原始 MP4、显式且不重叠的缩放区间，以及已定义的左键点击。多显示器、暂停/多段、剪辑倍速、右/中键、自动缩放生成、光标静止隐藏/旋转/循环、按片段禁用平滑、瞬时缩放、缩放跟随鼠标、运动模糊与 Screen Studio 样式的精确匹配均不属于首期验收。

## 尚待决定或后续验证

- 是否将首期平滑固定为一种算法，或暴露“关闭/平滑”两档；公开资料不够支持按 Screen Studio 的 Smooth/Medium/Rapid 数值仿制。
- 点击反馈应以视频像素固定大小，还是随缩放同比例放大；当前建议固定输出像素大小，须由成片可读性确认。
- `followCursor` 的相机滞后、死区、更新节流和多次点击目标切换规则；需要可播放的样本或用户期望视频再定。
- 短区间（小于进入加退出时长）是压缩两段、跳过停留，还是改用瞬时效果；上文建议前者。
- JSON 是否沿用 `follow-click-groups` 等 Screen Studio 字段名。第一阶段更适合采用面向本项目的显式字段，避免暗示格式兼容或内部行为等价。
- 若后续重新获得可视预览权限/接口，应制作至少三组受控样本：单击后停留、连续远距离点击、下拉菜单；逐帧比较点击触发点、光标形状切换、进入/退出长度和跟随轨迹。届时才能把上述建议校正为观察结论。
