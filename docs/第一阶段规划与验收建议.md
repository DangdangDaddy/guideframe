# 第一阶段规划与验收建议

状态：2026-09-11 第一阶段 CLI 已交付实现，最终全量测试44项通过。下文调研阶段的建议作为历史背景；实际行为、限制和已执行验证分别以 docs/session格式.md、README.md、docs/第一阶段验证报告.md 为准。离线安装包、跨播放器及大规模性能基准并非本轮已完成验证。

## 目标与范围

以无光标的原始 MP4 和 Screen Studio 兼容鼠标事件为输入，通过独立的本地渲染核心输出 MP4、短 GIF 和指定时间的渲染结果 PNG。

首阶段按明确的缩放区间执行放大、停留、还原。根据点击自动生成缩放区间作为独立策略，是否首阶段纳入需明确，不能与时间轴执行能力混为一谈。

桌面界面、录制、云端服务不进入第一阶段。

## 验收证据要求

1. 坐标：覆盖非零录制区域偏移、不同视频尺寸、热点偏移、缩放后点击对齐；先用已知几何的合成样例验证，再检查真实录制。
2. 时间：按视频时间戳采样，不按鼠标数组序号推断时间；覆盖首条事件晚于视频起点、长时间停留、相同时间戳和事件边界。
3. 平滑：控制抖动的同时保证点击时光标命中，不能仅以“更平滑”的视觉印象判定成功；具体容差在规格中明确。
4. 缩放：验证进入、停留、退出的边界值与连续性，规定重叠区间和目标越界的处理方式。
5. 导出：验证媒体可解码、尺寸/时长正确，PNG 包含同时间的光标/点击/缩放效果，GIF 使用指定时间片；音轨策略需在规格中明确。
6. 安全写入：源文件不变，输出冲突有明确行为，中断/失败不留下冒充成功的输出。
7. 完全离线：准备依赖后可在断网环境执行完整合成演示；不登录、不上传、不发送遥测。

## 调研审查标准

- 区分原始文件或官方文档的事实、基于样本的推断、本项目建议。
- 两份单段区域录制不能代表多显示器、多分段、所有光标或所有鼠标按钮。
- 采集流尺寸与最终视频尺寸分别核验；显示器刷新率不能直接作为视频帧率。
- 公开效果描述不能证明商业软件的内部算法；建议参数不能标成 Screen Studio 默认值。
- 报告只使用必要的结构信息，不收录键盘内容或无关私人画面。

## 本轮审查后的收敛建议

以下为规划建议，尚未进入实现：

- 兼容鼠标移动和点击 JSON 字段结构，关联录制分段元数据；不要求读取完整 Screen Studio 编辑工程。
- 首期限定单段原视频，缩放使用显式、不重叠区间，固定目标；自动按点击生成、跟随、瞬时缩放及片段平滑控制不进入最小规格。
- 事件相对时间使用录制分段起点，坐标按真实视频尺寸与 bounds 映射。两份实际样本均为 2774×1290、可变帧率；不要把样本的 2 倍坐标比例写成通用常量。
- 输出建议使用固定帧率的时间网格；按输入 PTS 选择对应源画面，按每个输出时间点计算鼠标、点击和缩放，以支持稀疏原视频中的连续动画。
- 点击时间作为轨迹锚点；热点偏移须随光标最终绘制尺寸一起缩放。
- 输出有音轨时建议保留，并明确复制/转码和同步规则；PNG 是指定时间的完整渲染画面，GIF 为明确时间片的同一渲染结果。
- 2倍缩放、250ms进入/退出、380ms点击反馈等仅是效果报告中的候选值，不能称为已验证的最佳参数或 Screen Studio 默认值；应在合成样例成片评审后定稿。

## 进入开发前的交付门槛

下一步如用户允许开发，先由 Sol 子代理提交输入契约和最小实现计划，主代理审查后分配实现任务。规格必须落实以下常规技术选择，不需要把每个实现细节都回问用户：

1. 输出帧率/尺寸默认值、奇数尺寸处理和视频时长边界。
2. 首个事件前及末个事件后的光标状态，同时间事件顺序、缺失光标的回退策略。
3. 平滑算法及点击锚点约束，缩放曲线、短区间处理与目标边界规则。
4. 音轨选择、同步与转码策略，GIF时间片和PNG帧选择规则。
5. 依赖获取/固定版本与离线运行准备。

仍需实际验证的事项：合成靶标上的点击/热点像素误差、视觉流畅度、真实环境编码能力和性能。现阶段不对这些事项声称通过。
