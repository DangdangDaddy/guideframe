## 结论

第一阶段的代码级与代表性媒体验收已通过。本轮实际执行全量测试，最终结果为 `44 passed in 1.12s`。纯合成的 VFR+AAC 源素材已通过同一条渲染路径生成 MP4、GIF 和 PNG；另外用一份用户本地 Screen Studio 原始录制做了一次只读 MP4 渲染。

| 文件 | 实测结果 |

`input-sha256.json` 中的四份输入摘要在三种输出生成后全部保持不变。无效/不支持的输入会在成品发布前失败；输出目标已存在时拒绝覆盖，模拟失败后未留下冒充成品的临时文件。

抽取 0.00、1.15、1.50、2.65、3.18、4.85 和 6.40 s 画面做了人工视觉检查：进入、停留和退出连续，两个边缘镜头未显示黑边，4.85 s 附近的光标尖端和点击靶点对齐。在源画面 1.92–3.32 s 无新 PTS 的时段内，输出仍有 30 fps 光标运动；比较 1.933 s 与 2.000 s 帧时，显著变化集中在光标区域，全画面平均绝对通道差小于 1。

无效果的首帧对 6 个实心 UI 色块采样，第二次 H.264 往返后单通道误差不超过 4。这是样例色块的有限检查，不等同于完整黑白阶、色域或专业色彩准确性验证。

## 真实本地录制验证

本轮对用户本地的第二份 Screen Studio 单段区域录制执行了一次只读渲染。源 MP4 和鼠标事件继续位于原项目中，未复制、未修改；渲染前后源 MP4 的 SHA-256 完全相同。为保护私人画面，本报告不嵌入截帧或原路径。

本地验证输出为 `tests/output/real-sample-render.mp4`（已明确排除出版本库），实测为：

- H.264 `yuv420p`，2774×1290，143 帧，15 fps CFR，9.533 s；
- 原素材无音轨，输出也为静音；
- colorspace/primaries/transfer/range 均为 BT.709 limited 对应枚举值 1；
- 完整解码 143 帧成功；
- 抽取约 4.733 s 点击时刻检查，后期光标已叠加，尖端落在目标控件上，画面尺寸与方向正常。

这次真实样本为无缩放、15 fps 的代表性渲染，不是速度基准或 Screen Studio 外观逐帧对比。

## 音频、安全写入与离线边界

两个小型合成音视频回归分别覆盖了音轨晚于视频开始和音轨早于视频开始：

- 晚起音轨走 stream copy，输出起点保持为约 0.20 s；
- 早起音轨主动走 AAC + trim，输出音轨起点为 0，输出视频帧数和时长与探测到的视频呈现区间一致，没有因较短音轨截断视频。

本测试只核对流起点、帧数和时长，未生成视听脉冲并测量内容级 A/V 偏差，也没有做主观听感验收。

运行时的媒体可执行文件由固定的 `imageio-ffmpeg` wheel 目录直接选取，不使用 PATH 或其他应用的 FFmpeg。输入仅接受本地普通文件，URL/URI 会被拒绝；项目 Python/脚本未检出网络请求、上传或遥测代码。本轮在正常网络环境中使用已安装依赖运行，没有断开系统网络做动态抓包或防火墙验收。
