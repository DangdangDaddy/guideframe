# 第一阶段代码审查

日期：2026-09-11

## 审查范围

本轮只读审查 `local_demo/media.py`、`local_demo/cli.py` 和 `local_demo/demo.py`，范围限定为第一阶段正常输入下的媒体时间戳、短 GIF、输出文件安全、失败清理、色彩/解码限制和 CLI 错误路径。没有修改媒体业务代码，也没有重复执行完整编码。

## 发现与修复状态

1. **短 GIF 帧数校验错误，已修复。** 原实现按完整视频时长计算期望帧数，但 CLI 和合成演示只渲染 `[gif_start, gif_end)`，会使正常短 GIF 在编码后验证失败。当前 `export_gif` 接受调用方传入的 `expected_frames`，CLI 按同一半开区间计算；演示不再用完整视频帧数误判时间片。
2. **未知或早于视频的音频起点可能产生负 PTS，已修复。** 当前只有已知 `audio_start_seconds` 且不早于首个视频 PTS 时才尝试音轨复制；未知或更早的起点走 AAC 与 `atrim` 分支。第二个 FFmpeg 输入也单独限制为本地 `file,pipe` 协议。
3. **旋转检查可能漏掉流级 display matrix，已修复。** 当前同时检查 `stream.side_data` 和解码帧 `side_data`，首阶段遇到旋转素材会明确拒绝，避免画面尺寸与鼠标坐标方向不一致。
4. **输出发布和失败清理未发现新的首期阻塞问题。** 输出使用同目录临时文件，成功验证后以不覆盖已有目标的硬链接发布；编码、验证或中断失败时清理临时媒体及 GIF 调色板。输出与 session、视频和外部事件文件的别名受到保护。

## 验证边界

此前渲染核心的独立验证为 `tests/test_session_and_timeline.py` 与 `tests/test_renderer.py` 共 31 项通过；这是核心实现阶段的历史证据。本轮媒体审查没有据此声称全量测试或端到端导出通过，当前全量结果以独立验证任务的最终报告为准。
